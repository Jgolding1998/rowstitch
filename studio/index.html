Rowstitch is a SQLite library for your Node app. This page is its read-only trace viewer. How to use it

The library

You install it in your own Node.js project. Your code defines tables and runs queries against your SQLite file. It can save a trace of the SQL it ran.

Studio, this page

It opens those trace files so you can read the SQL, transactions and plans. It never connects to a database or runs SQL, and the file stays in this tab.

Four steps

  1. 1

    Look around the fictional demo. It loads when this page opens and is made up for this visit.

  2. 2

    Add the library to your Node project. It is installed from its GitHub release, so use the current command in the README.

    Install instructions in the README
  3. 3

    Save a trace from your code. Bound values are redacted unless you turn them on.

    import { writeFileSync } from 'node:fs';

writeFileSync('trace.json', JSON.stringify(db.exportTrace({ title: 'My app' })));
  4. 4

    Open the trace here. Start this page from your project with npx rowstitch demo, then choose the file or drop it onto the window. Use the Node release the README requires.

        Before you share a trace

        Redaction is not anonymization. Bound values may be replaced with [redacted], but the title, table and column names, SQL text, statement counts and timings stay readable, and they can reveal what an application does and how its data is shaped.

        Write effects such as "Committed" or "Undone" are read from the order of BEGIN, SAVEPOINT, COMMIT and ROLLBACK statements in this file. They describe this trace only, not the current database or whether your application's call succeeded. A file can be edited, so treat them as a reading aid, not proof.

        This page shows what is in the file and nothing else. It keeps the trace in this tab's memory only, makes no requests besides loading the fictional demo from this local server, and never executes SQL. Export downloads the trace exactly as loaded. Clear removes it from the page.
